# 設計指南

這一頁描述網站**是什麼、長什麼樣、文章怎麼寫**。內容、階段、頁面順序會變；讀完仍該認得這是同一個站。

它不取代另外兩份文件：

| 文件 | 它回答 |
|---|---|
| [ARCHITECTURE.md](ARCHITECTURE.md) | 數字從哪一層來，頁面碰得到哪一層 |
| [SITE_RULES.md](SITE_RULES.md) | 哪些事情讓建置失敗 |
| 本指南 | 換一篇文章、重排一頁時，語氣、顏色、圖、版面仍是這一家 |

能自動檢查的條目在第 4 節對回規則編號。規則沒寫到的外觀，以這一頁為準，並在該節建議新的檢查。

分冊：

- [design/visual.md](design/visual.md) — 顏色、字、間距、數字格式、徽章
- [design/charts.md](design/charts.md) — 圖的種類與游標
- [design/pages.md](design/pages.md) — 頁面骨架、四種模板、文章與網址怎麼管

現況對的是 2026-11-15 的 `app/src/styles/tokens.css`、`app.css`、`lib/format.ts` 與圖表元件。下面若寫「現況」與「契約」兩欄，契約是往後要守的；現況是程式今天實際的樣子。

## 1. 這個站是誰的

`index.html` 的標題是「MSTR 資本結構解剖」，`lang` 是 `zh-Hant`。

它服務一個問題，寫在 `CLAUDE.md` 與 `reference/00-purpose.md`：比特幣有限，這家公司要長期贏過比特幣，只有一種做法，就是**每股含幣變多**。工具的演進是把風險往外推（抵押借錢、可轉債、永續優先股）。推出去之後，優先股若跌破面額，公司仍得把它拉回面額，才能再發行、再買幣。

讀者懂股價，不一定寫過公式。他來這裡是要核對一個數的口徑與出處，不是要一句買賣建議。頁尾現在寫「本頁為資料分析，不構成投資建議」。這個句子留在每一種模板的頁尾。

### 語氣

| 要 | 不要 |
|---|---|
| 先給數，再給一句它在回答什麼 | 用形容詞代替口徑（「很便宜的 mNAV」） |
| 兩個 mNAV 並排，各帶名字 | 只寫 mNAV |
| 求償權寫出三項：可轉債面額、優先股清算優先權、現金 | 只寫一個合計，讓人猜有沒有扣現金 |
| 沿用、直線、重建，用徽章上的字說出來 | 把最慢的那一欄說成整頁的新鮮度 |
| 機制解讀寫下一句可被後來的資料檢驗的主張 | 在儀表板寫「這是好決策」。`board.ts` 的註解已經禁止這句 |
| 文章裡的數是寫作當日釘住的，旁邊另給今天 | 改寫舊文，讓當時的數悄悄變成現在的數 |

正文是繁體中文。標點用全形逗號與句號。代碼、指標 id、單位符號（BTC、sats、USD）維持英文。日期寫 `YYYY-MM-DD`，不寫「10 月 1 日」當唯一形式，因為截至日要比對。

數字句的形狀：

> 淨求償權 $14.76B（截至 2026-10-01；債務沿用 2026-06-30）＝ 可轉債 $6.67B ＋ 優先股面額 $14.11B − 現金 $6.02B。

股價若拆開，三個顯示值要乘得回顯示的股價，單位寫在數字裡（`162,003 sats ＝ 0.00162003 BTC`）。這是 [SITE_RULES.md](SITE_RULES.md) R15 要檢查的那句話，這裡規定它長在句子裡的樣子。

### 詞彙

同一個詞只有一個意思。括號裡是指標 id，定義在 `mstr_cebe/core.py` 的列舉。

| 詞 | 意思 | 不要用來指 |
|---|---|---|
| 持幣 | 公司持有的比特幣顆數。預設是 8-K 週報的階梯 | 日頻上兩點之間的斜線 |
| 求償權 | 不單獨使用。要寫後面四個名字之一 | 一個沒說口徑的合計 |
| 淨求償權 `claims.cebe` | 可轉債面額 ＋ 優先股清算優先權 − 資產負債表現金。`ClaimsBasis.CEBETRACKER` | 毛額，或扣的是 USD Reserve 的那一版 |
| 毛求償權 `claims.company` | 面額合計，不扣現金。`ClaimsBasis.COMPANY` | 淨求償權 |
| 官方淨額 | 毛額減 USD Reserve。`COMPANY_NET_RESERVE`。只在對官方錨點時出現 | 本站預設讀數 |
| basic mNAV `mnav.basic` | 全部持幣相對 basic 股數。公司公布的 BTC Yield 用這組 | CEBE，或沒寫 basic 的「mNAV」 |
| CEBE mNAV `mnav.cebe` | 扣掉淨求償權之後，股價相對剩餘比特幣 | basic |
| 帳面每股 | 持幣 ÷ basic 股數，單位 sats。式子裡沒有求償權 | 官方 Gross BPS（那個分母是 assumed diluted） |
| 實得每股 | 扣掉淨求償權之後每股的比特幣，單位 sats，並能換算回顆 | 帳面每股 |
| 面額 | 清算優先權。優先股是 stated amount（五檔都是 100，本幣）× 股數 | 市價 |
| 市價 | 收盤價。STRE 沒有公開報價時是空，不是 100 | 面額 |
| 美元資產 | Reserve 與 Cash 分開列，加總時寫明兩項 | 把 2026-08-24 FWP 的 $6.69B（Reserve $5.10B ＋ Cash $1.59B）叫成儲備 |
| USD Reserve | 管理層指定用途的那一筆美元 | 資產負債表現金 |
| 沿用 | 最後一筆觀測之後，數值不變 | 插值 |
| 直線 | 兩個申報錨點之間的線性補點。`method = linear` | 持幣的預設圖 |
| 重建 | 不是文件上的餘額，是用其他列反推（優先股股數對季末、單一歐元匯率） | 8-K 明寫的持幣 |
| 假設 | 滑桿的輸入與輸出。不是歷史 | 當天的槓桿讀數 |
| 主張 | 機制解讀文章裡那一句，寫下之後用後來的資料檢驗 | 大事記。大事記錨在事件，沒有主張欄 |

五檔優先股的代碼固定寫 STRF、STRC、STRK、STRD、STRE。STRC 是被拉回面額的那一檔（浮動股息與折價回購）。其餘固定利率的價格不構成「能不能再發行」的閘門。這個區分寫在總覽的閘門卡，換頁時保留。

## 2. 分冊怎麼用

改一個顏色或一張圖之前先讀分冊。改一篇文章的措辭不必改分冊。若新的圖不屬於 [design/charts.md](design/charts.md) 列出的種類，先在那一頁加一種，再在頁面上用它。

第 7 層（頁面與敘事）在 [ARCHITECTURE.md](ARCHITECTURE.md) 裡可以整份換掉。換掉之後，這一指南的顏色、詞彙、圖的筆畫、文章的釘仍然有效。

## 3. 固定與自由

| 固定。改了要改本指南，並讓第 4 節的檢查跟著改 | 自由。登錄、文章、順序怎麼改都行 |
|---|---|
| 繁體中文、日期格式、詞彙表 | 哪一頁先出現、標題、段落 |
| 一檔證券一個顏色，全站同一支對照表 | 一頁放哪些已登錄的圖 |
| 持幣用階梯；直線與假設用另一種筆畫 | 圖是全寬還是並排 |
| 數字走 `lib/format.ts` 的格式 | 句子怎麼起頭 |
| 閱讀頁開頭三行：問題、截至、口徑 | 三行下面是圖還是表 |
| 文章左欄是寫作當日，右欄是今天 | 舊文留著，或在文末加一則日期註記 |
| 頁尾不做投資建議 | 窄螢幕用抽屜還是把導覽折成兩行，只要每一頁都點得到 |
| 四種頁面類型各自的內容界限 | 類型之內的區塊順序，除了開頭三行 |

## 4. 哪些已有規則，哪些建議再檢查

| 本指南 | 已寫進 SITE_RULES |
|---|---|
| 詞彙表的求償權與兩種 mNAV | R6 |
| 面額與市價分開，STRE 價格留空 | R5 |
| 單位與三個顯示值乘回股價 | R4、R15 |
| 徽章上的 as-of 與 method | R3、R7、R13 |
| 滑桿是假設 | R8 |
| 四種模板 | R10 |
| 頁面登錄與重新導向 | R9 |
| 文章用釘，不手打會過期的數 | R11。現況的釘是 `Post.pins` 的「寫的時候／今天」表，見 [design/pages.md](design/pages.md) |
| 出處是文件 id | R12 |

建議加、尚未寫進規則的檢查：

1. **顏色只准 token。** `app/src` 裡除了 `tokens.css`，不出現 `#` 十六進位。疊加遮罩的 `rgba` 只准在一張允許清單（現在是燈箱的 `rgba(0,0,0,.62)` 與陰影）。證券色只從一張對照表來，例如 `FUNDING_COLOR` 那種物件，禁止圖裡直接寫 `var(--c3)` 表示「另一條線」。
2. **圖只從圖庫來。** `pages/` 不組 SVG path。新圖是 `app/src/charts/` 裡的一個函式，頁面只傳指標 id 與區間。
3. **格式只走 `lib/format.ts`。** 頁面檔出現 `toFixed` 且對象是金額、股數或 sats，即失敗。百分數與倍數用 `pct` 與 `mult`。
4. **徽章的 class 屬於 method。** `live` / `near` / `far` 這組「插值距離」徽章退役之後，節點的 `data-method` 只能是 `observed`、`step`、`carry`、`linear`、`spliced`、`reconstructed`、`assumed`。
