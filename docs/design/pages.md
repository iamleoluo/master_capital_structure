# 頁面與內容

回到 [設計指南](../DESIGN_GUIDE.md)。類型的邊界由 [SITE_RULES.md](../SITE_RULES.md) R9、R10、R11 檢查。這一頁寫那些類型長什麼樣、文章怎麼進站、舊網址怎麼留。

---

## 1. 四種模板

站上現在的目錄與類型的對應：

| 類型 | 現在的目錄 | 這類頁在做什麼 |
|---|---|---|
| `reading` | `pages/overview.ts`、`pages/board/*`、`pages/pricing.ts` | 給已登錄的數、圖、表 |
| `method` | `pages/lecture/*` | 只有公式。`lectureHead` 寫明「這一頁不帶任何數字」 |
| `note` | `pages/posts/*` | 大事記與機制解讀 |
| `source` | `pages/provenance.ts` | 文件、粒度、已知矛盾 |

不另開第五種類型。定價頁的滑桿仍是 `reading`，假設區塊放在歷史的下面，用視覺系統的假設徽章，不因此變成新類型。

### 閱讀頁

```
┌ 眉題                          價格截至 …… · 持幣截至 …… 申報 · 今天 …… ┐
│ 標題。一句這頁在問的問題                                                    │
│ 口徑一行（若這頁有求償權：淨求償權＝…）          算法 →                      │
├ 磁貼 磁貼 磁貼 磁貼 ─────────────────────────────────────────────────────────┤
├ 圖 ─────────────────────────────────────────────────────────────────────────┤
│ 圖說。方法與出處                                                            │
├ 表（可橫向捲）──────────────────────────────────────────────────────────────┤
└ 頁尾：資料從哪來，以及不構成投資建議                                        ┘
```

開頭三行的材料來自頁面登錄的 `question`、各指標的 `asOf` 與 `method`、口徑的 `label`。算法連結指向 `method` 頁，放在三行的右側，不放在數字前面。`boardHead` 現在是「資料至某一天」加一段方法論；契約把它收成這三行，方法論留在 `method` 頁。

磁貼是 `.tile`：眉題、等寬數字、一行定義、必要時一顆方法徽章。一顆磁貼一個指標。

### 算法頁

`components/lecture.ts` 已規定每一節是四段：問題、推導、怎麼驗、邊界。編號在左線上。公式用 KaTeX。正文不出現觀測值，這是 `tests/test_lecture_is_formula_only.py` 在守的。

頁首可以指向對應的閱讀頁（「今天的數在儀表板」），閱讀頁指向這裡。兩頁不互相複製段落。

### 筆記頁

清單分兩類，`posts/list.ts` 已經寫了差別：大事記錨在事件；機制解讀多一個「主張」，主張要能被後來的資料檢驗。空清單時說明這一類該放什麼，不留一個空白標題。

一篇文章的骨架（`posts/detail.ts`）：

1. 眉題連回該類清單，標題，日期，作者，標籤。
2. 若有主張，放在 `.note.key`。
3. 釘的表：「寫於 {date} 的數字，與今天的對照」。左欄不更新，右欄每次建置重算。分岔本身是資訊。
4. 正文 HTML，由 markdown 在建置期轉好。
5. 若文章帶 `era`，底下掛那段由管線算的骨架，不在散文裡再寫一套數。

### 出處頁

檔案庫、粒度、對帳、`FINDING_*`。第一段用白話。同一段說明只出現一次。已知矛盾與 mnav.com 那種變體留在這裡，不進閱讀頁的預設磁貼（R17）。

## 2. 區塊目錄

新頁只組這些塊，不為一篇文章新做一種卡片。

| 塊 | class / 元件 | 裝什麼 |
|---|---|---|
| 頁首 | `.page-head` | 眉題、h1、導語 |
| 三行 | 登錄產生 | 問題、截至與方法、口徑、算法連結 |
| 磁貼列 | `.grid3` ＋ `.tile` | 一指標一格 |
| 讀數條 | `.reading-grid` | 探索器當天的一行數，6／3／2 欄 |
| 恆等式 | `.eq` | 三項，結果用 `--equity` |
| 圖 | `.chart-block` ＋ `charts/*` | 見圖的語法 |
| 圖說 | `figcaption` | 方法與出處，不重講口徑全文 |
| 表 | `table.mini` 放進 `.scroller` | 數字欄 `.n` |
| 註 | `.note`、`.note.key`、`.note.warn` | 一句邊界或主張 |
| 階段卡 | `.era`、`.latest-era` | 時期的標題與管線算的變化 |
| 公式卡 | `.eq-card`、`.lec-step` | 只在算法頁 |
| 釘 | `.pins` | 只在筆記頁 |
| 頁尾 | `footer` | 五檔優先股、STRE 無報價、不構成建議 |

內文寬超過 1120px 的只有燈箱（最寬 1400px）。燈箱是同一張圖，不是另一種頁。

## 3. 頁面怎麼加減

登錄一列就是一頁（R9 的 JSON）。現況仍是 `app/src/main.ts` 裡的 `routes` 陣列，子頁用 `parent`。遷到登錄之前，加減頁仍改這個陣列，但照下面的欄位想：

| 動作 | 怎麼做 |
|---|---|
| 新增 | 新的 `id`、`path`、`type`、`title`、`order`、`question`、要用的指標。模組放在對應類型的目錄 |
| 改順序 | 只改 `order`。不為了順序去改路徑 |
| 改名 | 改 `title`。`id` 與 `path` 不動，舊文章與外部連結還指得到 |
| 退役 | 從主導覽拿掉。`path` 留在 `redirectFrom` 指到替代頁，或指到出處頁說明這頁收起了。不把 hash 變成空白然後落到首頁 |
| 拆頁、併頁 | 舊 path 各寫一條重新導向。閱讀頁不複製算法頁的段落來「免得讀者點走」 |

未知 hash 今天會落到路由陣列的第一筆（`router.ts`）。契約：未知路徑有明確的一頁，不隱含「陣列第一個」。

現有 path 要留的重新導向，在頁面真的改名時一次寫進登錄，而不是等連結壞了再補：`/lecture/*`、`/board/*`、`/pricing`、`/posts/*`、`/provenance`。在改名發生前，這些 path 就是正身，不必先做空的轉址。

頂列只放閱讀頁與筆記。算法與出處在頁尾與三行右側。這是現在這份指南的預設，不是規則。規則只要求登錄裡的每一頁都進得了選單的資料；窄螢幕把頂列裁掉才是視覺契約要修的（見視覺系統）。

## 4. 文章怎麼寫、舊文怎麼留

一篇筆記是一筆 `Post`（`app/src/types.ts`）：

| 欄 | 規則 |
|---|---|
| `slug` | 穩定。改標題不改 slug |
| `date` | 寫作日 `YYYY-MM-DD`。不隨改稿更新 |
| `kind` | `chronicle` 或 `structure` |
| `claim` | 只有 `structure` 有。一句話，能被後來的資料說是或不是 |
| `era` | 可空。有值就掛上那段的計算骨架 |
| `pins` | `{ key, label, then, now, unit }`。`then` 是寫作當日的快照，進版之後不改。`now` 由建置填 |
| `html` | 建置期由 markdown 轉出。散文裡不寫第二套會過期的金額 |
| `charts` | `{ id, from?, to? }`，id 必須是圖庫裡的種類 |

釘的表已經做在 `posts/detail.ts`：左欄「寫的時候」，右欄「今天」，註明左欄永遠不變。這就是文章管理的方法。R11 建議的 `{{metric:id@date}}` 是同一件事的檢查用寫法；在那個語法落地之前，手寫進 `pins` 且 `then` 不回寫，就是守住這條的方式。

敘事變了的時候：

| 情況 | 做法 |
|---|---|
| 錯字、文句不清楚 | 改 `html`。不改 `date`，不改 `pins.then` |
| 主張被後來的資料推翻 | 原篇留著，主張與左欄保留。新寫一篇，日期是今天，開場連到舊篇。不把舊主張改成新結論 |
| 階段邊界重劃 | `phase` 的起迄可以改，因為它是編輯過的時期，不是申報。改動要出現在 diff 裡。已經釘在舊邊界上的文章不跟著改 `era`，除非作者明示這篇要改掛；原文的釘仍指向寫作當日 |
| 指標口徑改了 | 右欄用新口徑重算，左欄不動。若左欄的單位因此無法對照，右欄顯示 `—`，表下說明口徑從哪一天起不同。現況是對不到 key 就只顯示當時的值 |
| 整段敘事不再放在導覽 | 筆記頁可以從頂列拿掉，path 轉址到清單或出處。文章的 slug 仍可開啟 |

階段條上的名字來自大事記的 `title`。短到畫不下的那段改列在軸下，不從資料裡刪掉。進行中的階段用徽章，不用把迄日填成「估計的未來」。

## 5. 網址

現在是 hash 路由：`#/posts/structure/<slug>`、`#/board/quantities`。沒有另做一套路徑。對外提到某一天的讀數時，網址不必帶日期；日期寫在頁首與釘裡。游標是閱讀狀態，不寫進 hash，避免分享一個連結卻因對方的游標停在另一天而看到不同的磁貼。若以後要把「某一天」分享出去，那個日期是查詢參數，頁首跟它走，而不是讓磁貼與圖各看各的。
