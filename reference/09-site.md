# 09 — 網站的設計:理論 / 觀測 / 詮釋

這份文件回答「**網站要做什麼**」,以及為什麼它要分成三個性質不同的部分。
模型本身在 [01](01-model.md) 與 [02](02-operations.md),這裡只講**呈現的架構**。

---

## 0. 為什麼要重新分

現在的網站是七個平行的頁面:

```
總覽 │ 大事記 │ 資本結構 │ 資本操作 │ 績效歸因 │ 槓桿與定價 │ 資料品質
```

這是**儀表板的排法**:每一頁回答一個問題,順序無所謂。但這個系統的內容
其實有一條構築線 —— [01-model.md](01-model.md) 就是照那條線寫的:

```
四個原始量 → 求償權怎麼算 → 哪個股數分母 → 兩把尺 → 槓桿
→ 股價恆等式 → 取對數 → 拆開決策與行情 → 四層 → 哪一筆操作
```

網站沒有照這條線走。**總覽第一頁就把 $P = m \cdot E/10^{8} \cdot p$ 攤開,
但 $E$ 要到第三頁的子分頁才定義。結論在前,前提在後。**

更根本的問題是:**三種性質不同的內容被混在一起。**

---

## 1. 三個部分,三種性質

| | 性質 | 回答 | 用什麼表達 | 會不會變 |
|---|---|---|---|---|
| **一 · 講義** | 理論 | 這台機器怎麼運作 | **代數** | 幾乎不變 |
| **二 · 儀表板** | 觀測 | 現在的讀數是多少 | **數字** | 每週 |
| **三 · 觀點** | 詮釋 | 這些數字該怎麼看 | **論述** | 有新的就加 |

分界線是硬的:

> **講義不碰現價,儀表板不碰公式,只有觀點才告訴你怎麼看。**

這不是排版偏好,是認識論上的分工。**數據本身是中性的** —— 把「怎麼看」
混進儀表板,讀者就分不出哪些是算出來的、哪些是某個人的判斷。
而這正是 [00-purpose.md §4](00-purpose.md) 說的「決策工具最危險的失敗模式
是看起來給了答案,其實只是把假設重講一次」。

## 2. 第一部分 — 講義

### 2.1 四層:從代數到真實參數,再到時間

| 層 | 內容 | 對應後端 |
|---|---|---|
| **一 · 量與尺** | $H, C, S, p$ 為什麼只需要四個;$C = D + L - U$;三個股數分母;$B, E, m, A, p_0$;$m$ 的分母為什麼必須是 $E$ | 純代數 |
| **二 · 工具** | 四個位置、八條箭頭(見 §2.2);每條的 $\Delta B / \Delta E$ 與判準;組合 | `toolbox` |
| **三 · 真實參數** | 那四個量**真實的值從哪來**:申報原文怎麼歸檔 → 怎麼變成具名事件 → 怎麼配對成資本操作 | **L1 → L2 → L3** |
| **四 · 時間** | 加入時間序:逐日鏈結、為什麼要用當天的價格評價、四層歸因、階段 | **L4** |

每一節的結構固定:**問題 → 推導 → 證據 → 這一層的邊界在哪**。

> ⚠️ **第三層不是附註,是構築線的一段。** 這份文件的第一版把它降級成
> 「資料品質溶進每層」加一頁出處,等於把 L1→L2→L3 整套從講義裡拿掉了 ——
> 但「這四個量真實的值怎麼建立起來」正是前面兩層與後面一層之間的橋:
> 沒有它,代數接不到時間軸。
>
> 資料品質(插值、粒度、面額 vs 市價)仍然**溶在儀表板的每個數字旁邊**
> —— 那是「這個數字能信多少」;第三層講的是**「這個數字是怎麼來的」**,
> 兩件事不同。

**這一層與 [06-architecture.md](06-architecture.md) 的 `L1–L4` 是同一套東西**
—— 06 寫的是工程規格(資料結構、介面、驗收條件),這裡寫的是**怎麼講給人聽**。
講義的四層刻意不用 `L` 編號,`L1–L4` 只屬於 06(見
[README](README.md) 的「兩條軸」)。

最後一項不能省。隨著時間推移與不確定性增加,**講義涵蓋得了的東西會變少** ——
恆等式永遠成立,但它不告訴你明天會怎樣。每一層都要明寫**它算得準的地方與
算不準的地方**,讀者才知道什麼時候必須離開講義、回到市場(第二部分)
與判斷(第三部分)。

### 2.2 工具那一層的主軸:四個位置,七條箭頭

每一個資本操作都是同一件事 —— **把錢在四個位置之間搬**:

```
        H 幣                   S 股數
          ↑                      ↑
   買幣 │ │ 賣幣          ATM │ │ 庫藏
          ↓                      ↓
        U 儲備  ←─────────────────
          ↕
   回購 │ │ 發行 / 股息
          ↓
    D + L 求償權
```

因為位置只有四個,**動作就是可窮舉的** —— 這是
[02-operations.md](02-operations.md) 用代數而不是用個案描述每一種操作的原因。

⚠️ **$U$ 不是「錢漏掉的地方」,它是 $C = D + L - U$ 裡的那一項。**
募資讓 $U$ 變大、$C$ 變小;花錢讓 $U$ 變小、$C$ 變大。所以
「ATM 募資 → 進儲備」**不需要另外配對** —— 那就是 `common_atm` 本身在做的事,
工具表裡 `sell_btc` 的標籤也直接寫著「賣幣進儲備」。

> 建置時繞過的彎路:曾經把 $U$ 當成殘差桶,去算「ATM 募資 → 回購優先股」
> 的金額差,結論是「配對不成立」。那是把狀態變數誤讀成漏損。

### 2.3 證據有三類,不要混

**講義不一定需要圖。** 對「工具」與「組合」而言,**能被驗證的對應關係本身
就是證據** —— 募了多少、進了多少儲備、買了多少幣,量體對得上就夠了。

| 類型 | 精度 | 例子 |
|---|---|---|
| **恆等式** | **0.000%** | $P = m \cdot E/10^{8} \cdot p$;逐日鏈結相消;四層加總 $= \ln$ 報酬 |
| **配對** | 0.0–1% | 賣幣→回購 STRC(文件明寫,差 0.0%);ATM→買幣(55 週,中位 0.6%);募資→儲備(對齊視窗後 0.2–1.1%) |
| **近似關係** | **要標明誤差** | $\mathrm{d}\ln E/\mathrm{d}\ln p = A-1$(單日大波動下中位差 10.4%);冪次成長 |

**第三類不是瑕疵,是教學內容。**「這條在單日 15% 波動下會差 16%,因為它是
導數不是等式」比假裝它精確有價值得多。

三類都應該是**可執行的斷言**。`reference/verify.py` 已經在驗第一類;
第二、三類可以用同一個機制加進去,讓「改了模型而講義沒改」會紅。

### 2.4 配對能不能成立,看兩件事

1. **文件有沒有明寫用途。** 用金額相似度去猜配對就是猜 —— 這是
   [06-architecture.md §5](06-architecture.md) 定下「配對看敘述、不看金額」的理由。
2. **你看的時間尺度。** 同一組關係在週尺度可能對不上、在季尺度就收斂
   (見 [03-data.md §2.3](03-data.md) 的解析度極限)。

## 3. 第二部分 — 儀表板

照講義的四層排,讓讀者對得起來,但**不重述公式**:

| 層 | 顯示 |
|---|---|
| 量 | BTC 價、MSTR 價、持幣、求償權、股數 —— 當下值 |
| 尺 | $B, E, m, A, p_0$ —— 當下值與走勢 |
| 工具 | 最近用了哪些工具、各多少錢(來自 L3 的具名操作) |
| 時間 | 歸因數字、目前在哪一個階段 |

**資料品質溶進每一個數字旁邊**,不另立一頁:這個數字是實測還是插值、
離最近的申報幾天、出處點得回哪一份 EDGAR 文件。讀者不該讀完全部才知道
哪裡不能信。

### 一條界線

儀表板可以顯示**代數直接推出的結果**(例如「$m = 1.167$,所以這筆增發對
既有股東是加分的」),因為那是講義的公式套用,仍然中性。

它**不能**顯示判斷(例如「這是好的決策」)—— 那屬於第三部分。

## 4. 第三部分 — 觀點

### 4.1 兩種文體,一套機制

| | **新聞**(大事記) | **社論**(資本結構) |
|---|---|---|
| 錨在 | 一個**時點或區間** | 一個**主張** |
| 問 | 發生了什麼、大概為什麼 | 對長期價值與本質有什麼影響 |
| 深度 | 報導事件表面 | 論述 + 資料佐證 + 數據分析 |
| 頻率 | 高 | 低 |

兩者會重疊 —— 但**當你開始重新思考公司的長期價值與本質,就進入社論**。

結構上的真正差異只有一個:**社論帶一個「主張」欄位,新聞沒有。**
因為主張可以被後續的資料檢驗,事件不行。

### 4.2 每一則是 repo 裡的一個檔案

寫作發生在 Claude Code 裡,所以每一則就該是可以 diff、可以 review 的檔案:

```yaml
---
title:  折價回購的套利空間還剩多少
date:   2026-10-02
author: Leo
kind:   editorial          # 或 news
tags:   [結構, 工具]
claim:  "折價回購在 m > 1−d 時對既有股東加分"   # 只有社論有
pins:   { decision_sats: 2468, strc_discount_pct: 4.1 }
charts: [{ id: perShare, from: 2026-06-29 }]
---
正文…
```

**圖表直接重用現有元件**(`drawPerShare` / `drawRiverBtc` / `drawAccumulation` /
`drawLeverage` / `drawMnav` / `drawPrice` / `drawEraStrip` / `drawRiverUsd`),
多數已經吃 `range` 參數,所以文章只要指名 ID 與區間就會得到跟全站同一套
樣式、而且是活的圖。

### 4.3 凍結的標日期,活的不要手寫

這是取代「手寫文字不得包含數字」的規則 —— 那條太嚴,會讓人根本沒辦法寫分析。

> **一篇文章引用的數字是寫作當下的快照,存在 `pins` 裡,永遠不改。
> 現況由資料層負責,永遠是今天。兩者都標明 as-of。**

#### 這條規則是怎麼來的

`chronicle.py` 的四段 Era 敘述是手寫散文,數字嵌在句子裡。查的時候發現:

| | 敘述裡寫的 | 管線現在算的 |
|---|---|---|
| 可轉債時代(已結束) | +43,129 | +43,129 ✓ |
| 優先股堆疊(已結束) | +21,115 | +21,115 ✓ |
| 壓力測試(已結束) | +576 | +576 ✓ |
| **折價回收(進行中)** | **+2,468** | **+3,105** ✗ |

**已結束的三段都還吻合,爛掉的正好是還在跑的那一段** —— 也就是最需要它
正確的那一段。問題不是「散文裡有數字」,是那些數字**沒有標日期,卻被當成
現況在顯示**。

#### 而且漂移可以反過來變成內容

```
寫於 2026-08-15:決策貢獻 +2,468 sats
(今天是 +3,105 —— 這個論點在那之後更強了)
```

**你能看到一個觀點寫下時的世界,以及它後來變成什麼。**
這對長期觀察有價值,而且只有「資料會自己更新、文章不會」的系統做得到。

## 5. 現有七頁的去處

| 現在 | 去哪 |
|---|---|
| 總覽 | 儀表板的首頁(四層的濃縮版) |
| 資本結構 · 求償權與殘值 | 講義 · 尺 |
| 資本結構 · 持幣與融資 | 儀表板 · 量 |
| 資本操作 | 講義 · 工具 |
| 績效歸因 | 講義 · 時間(推導)+ 儀表板 · 時間(數字) |
| 槓桿與定價 | 講義 · 尺(推導)+ 情境模擬器 |
| 資料品質 | 口徑與可信度 → 溶進儀表板各層;**出處與歸檔 → 講義 · 三 · 真實參數** |
| **大事記的四段 Era 敘述** | **轉成最早的四篇社論**,標上寫作日期;階段骨架只留起訖、一句定性、主要工具,其餘全部算 |

---

## 6. 這份設計刻意不做的

**不追求完全自我更新。** 講義的例子、社論的論述都是人寫的,不該、也不可能
自動生成。要自動的只有數字。

**不強制閱讀順序。** 四層照順序排,但隨時可跳 —— 對回訪的人強制解鎖很煩。

**不把觀點混進儀表板。** 寧可讀者多點一次,也不要讓判斷看起來像讀數。

**不做兩棵導覽樹。** 講義與儀表板是同樣四層的兩種模式,各自出現一次就好。

## 7. 還沒定的

1. **情境模擬器算哪一部分。** 它是「若幣價到 $X$ 則各項為 $Y$」的映射,
   不是預測 —— 嚴格說是講義的公式加上滑桿,但放進講義會讓講義變得很互動。
2. **作者欄位要寫誰。** 只有一個人,還是會出現協作署名。
3. **一次重排還是漸進。** 傾向漸進:先把四層骨架與總覽濃縮做出來,
   文章系統第二批 —— 四層的順序對了,文章才知道該掛在哪一層。
