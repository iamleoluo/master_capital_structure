# 00 — 這個系統是拿來做什麼的

**它是一個決策工具,不是一份研究報告。**

差別在於:研究報告回答「這家公司發生了什麼」,決策工具回答
**「我現在看到的這個價格,每一塊錢分別是什麼?」** —— 因為只有把價格拆開,
才知道自己在為哪一件事付錢,以及哪一件事變了會怎麼樣。

### 讀的順序

| | |
|---|---|
| **00**(這一章) | 要回答什麼 |
| **[01](01-architecture.md) 資本結構** | **標的是什麼形狀** —— 公司刻意蓋了什麼 |
| **[02](02-model.md) 模型** | 我們怎麼量它 |
| **[03](03-operations.md) 操作** | 它用哪些工具 |
| **[04](04-narrative.md) 敘事** | 溢價從哪裡來 |

01 在模型前面是刻意的。模型從四個原始量開始($H$、$C$、$S$、$p$),
但那四個量不是會計事實 —— **$C$ 是一座刻意蓋出來的求償權階梯**,
$S$ 的每次變動都是為了讓 $H$ 長大,而 $m$ 能大於 1 是因為有人全職在維持它。
先知道在蓋什麼,量出來的數字才有意義。

## 1. 核心輸出:把股價完全拆開

MSTR 的股價不是一個不可分割的數字。它是四個可觀測量的乘積與差,
而且**可以拆到誤差 0.000%**:

```
as of 2026-09-22 · MSTR $169.00 · BTC $86,404 · 415.9M 股

    每股帳面幣值      B/1e8 × p        $175.74      公司買了多少幣
  − 求償權吃掉        (B−E)/1e8 × p   −$ 35.68      排在你前面的人
  ─────────────────────────────────────────────
  = 每股殘值          E/1e8 × p        $140.07      真正屬於你的幣
  × 市場溢價          m = 1.207x                     市場願意付的倍數
  ─────────────────────────────────────────────
  = 股價                               $169.00      ✓
```

那 \$35.68 的求償權,還可以再往下拆到每一個券種:

| | 面額 | 每股 |
|---|---|---|
| 可轉債 | \$6.67B | \$16.04 |
| STRC | \$9.29B | \$22.33 |
| STRF | \$1.28B | \$3.09 |
| STRK | \$1.40B | \$3.37 |
| STRD | \$1.40B | \$3.37 |
| STRE | \$0.88B | \$2.13 |
| USD 流動性 | −\$6.09B | −\$14.64 |
| **合計** | **\$14.84B** | **\$35.68** |

**這就是這個工具存在的理由。** 看到 \$169 只是看到一個數字;
看到「\$175.74 的幣,被 \$35.68 的求償權吃掉,剩下 \$140.07,市場再加 20.7% 的溢價」,
才知道自己在買什麼。

## 2. 決策問題對應到哪個量

拆開之後,每一個常見的決策問題都有一個明確的對應量:

| 想問的 | 看什麼 | 在哪一頁 |
|---|---|---|
| 現在貴不貴? | $m$(CEBE mNAV)—— **不是**一般講的 mNAV | 總覽 / 槓桿與定價 |
| 我這一股背後有多少幣? | $E$ 實得每股含幣量 | 資本結構 · 求償權與殘值 |
| 公司的 KPI 好不好看? | $B$ 帳面每股 —— 跟上一項**常常反向** | 同上 |
| 跌到哪裡普通股歸零? | $p_0 = C/H$ | 槓桿與定價 |
| 幣漲 10%,我漲多少? | $A(p)$ 與 $A(p)-1$ 兩個彈性 | 槓桿與定價 |
| 這波漲幅有多少是公司做的? | 四層歸因的「公司決策」層 | 儀表板 · 時間 |
| 這一筆增發是加分還減分? | $m > 1$;若搭配折價回購則 $m > 1-d$ | 講義 · 工具 |
| 公司現在在用哪把工具? | 大事記的當期 | 觀點 · 大事記 |
| 這些數字能信到什麼程度? | 實測 vs 插值的邊界 | 出處 |
| 為什麼公司要發這麼多種優先股? | 把波動分層,轉移給另一個資金池 | [01 §1–2](01-architecture.md) |
| 公司會不會被強制平倉? | **不會 —— 沒有一層以幣設質** | [01 §3.2](01-architecture.md) |
| 股息付不出來會怎樣? | 股息水壩:高階沒付完,低階與普通股全部凍結 | [01 §3.1](01-architecture.md) |
| 現金夠付多久的股息與利息? | 跑道 $= U\,/\,$年化承諾 | ⚠️ **還沒進模型**,見 [09](09-data-gaps.md) |
| 溢價什麼時候會消失? | 反身性螺旋與規模陷阱 | [04 §6](04-narrative.md) |

**每一行的右邊都是一個式子或一條條款,不是一種感覺。**
推導在 [02-model.md](02-model.md) 與 [03-operations.md](03-operations.md),
條款與結構在 [01-architecture.md](01-architecture.md)。

⚠️ 表格裡有兩種不同性質的答案,不要混:
**上半部是可以算出數字的**(每一條都有恆等式守著);
下半部的「會不會被平倉」「股息水壩」是**條款**,算不出來,
要去讀申報文件;而「溢價什麼時候消失」只有**機制**,沒有數字,也不該有。

## 3. 為什麼框架比數字重要

數字每週都會變 —— 8-K 每週更新持幣、幣價每天在動、公司隨時可能發新的優先股。
**但拆解的結構不變**:

$$P = m \times \frac{E}{10^{8}} \times p, \qquad E = \frac{H - C/p}{S}\times 10^{8}$$

只要這兩條式子還成立,整個工具就還能用。所以這個專案真正在維護的
**不是一份報告,是一個會自己更新的框架**:

- 跑一次 `python3 web/build_data.py`,所有頁面的數字同步更新
- 加總恆等式在 build 時逐列斷言,對不上就讓建置失敗
- 兩個官方 FWP 錨點釘住管線,不讓它悄悄算錯
- `python3 reference/verify.py` 驗證這份文件裡的每一條式子仍然成立

**如果哪天公司發明了一種新工具,框架要能容納它** —— 那就是
[03-operations.md](03-operations.md) 用代數而不是用個案在描述每一種操作的原因。

而**結構層面也要能容納它**:新工具會接在求償權階梯的哪一層、
它剝走的是誰的波動、誰來買 —— 那三個問題的答法在
[01-architecture.md](01-architecture.md)。
2025 年一年之內多了五檔優先股,每一檔都是同一套邏輯的新切片;
**框架沒有因此改過形狀**,這件事本身就是框架對了的證據。

## 4. 這個工具刻意不做的事

決策工具最危險的失敗模式是**看起來給了答案,其實只是把假設重講一次**。
所以這裡有幾件事是刻意不做的:

**不預測幣價。** 定價頁的情境是「若幣價到 X,則各項為 Y」的映射,
不是機率預測。$p$ 永遠是輸入,不是輸出。

**不給投資建議。** 拆解告訴你在為什麼付錢,不告訴你該不該付。

**不用單一數字下結論。** 三五個月的窗口只能看到這台機器的某一個轉速 ——
大事記最上面永遠先給全期數字,就是為了擋住這件事。

**不把「行情」算成「公司的功勞」。** 這是整個模型最花力氣的地方:
$E$ 的式子裡有幣價,不拆開的話,幣價上漲會被誤讀成公司做得好。
見 [02-model.md §8](02-model.md#8-但中間那一層不是公司)。

**不隱藏口徑選擇。** 求償權按面額扣還是按市價扣,會得到不同的結論;
選了面額,就要把它偏在哪一邊寫在使用者看得到的地方。
見 [06-decisions.md](06-decisions.md#面額還是市價)。

---

## 5. 一句話

> 這個系統把 MSTR 的股價拆成**幣、求償權、股數、情緒**四件事,
> 讓每一次的決策可以指著其中一件說「我是為了這個」,
> 而不是指著整個價格說「我覺得會漲」。
