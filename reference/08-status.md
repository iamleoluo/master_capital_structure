## 3. 施工紀錄

原則:**每一步的驗收條件都是「既有的數字不能變」。** 這讓重構可以隨時
停下來,而且錯了會立刻被 23 條恆等式與現有測試抓到。

### ✅ 1–2. 建檔案庫,解析器改讀它

160 份 8-K(18.2 MB 原文壓成 1.7 MB)、內容定址、有出處。
四支解析器改用 `archive.iter_8k()`,並刪掉各自重複的候選清單邏輯。

驗收:封死 socket 之後仍跑得完,五份解析結果與 `web/raw/*.json` 逐筆相同,
下游 `app/data/*.json` 逐位元組不變。測試帶一個對照組,確認封鎖本身有效 ——
否則那個驗收沒有鑑別力。

一個當初沒想到的取捨:sqlite 每加一份就整檔重寫,git 存不了差異,
所以**內容不進版控、稽核軌跡進**(`web/archive/manifest.json`,每列有
url 與 sha256,任何人都能自己抓來對)。

### ✅ 3. 建 `events` 表,解析器改吐事件

916 個事件,週聚合改成 `weekly_*()` 視圖。三件實作時才看清楚的事:

- **動作與觀測必須在 schema 裡分家。** 持有量、USD 儲備、ATM 剩餘額度、
  回購剩餘授權都是**觀測**,沒有對應工具。混進動作就會把「餘額變了」
  讀成「公司做了什麼」。
- **「後蓋前」原本藏在 dict 覆寫的順序裡。** 現在是 `_latest_per_period()`,
  顯性而且可測試。
- **`total_m: null` 與「沒有這個欄位」不是同一件事。** 重建視圖時漏掉
  這個區別,70 筆裡有 1 筆對不上。這種等級的差異只有逐筆比對抓得到。

### ✅ 4. 歸因的參數改由事件產生(只完成一半,另一半是這一步的發現)

完成:資金流參數全部改由 `events.flows_between()` 算出,不再讀
`web/raw/*.json`。**559 個起點逐一位元級比對,零差異。**

沒完成,以及為什麼:**現行的操作表根本不是一組工具套用**,
它是一組長得像工具的<b>聚合差分</b>。

- `atm` 的參數是 $(n, P)$,但這裡只有整段期間的募資總額與股數淨變動,
  而股數淨變動混了轉股與庫藏,**本來就不等於 ATM 發出的股數**。
  實測有 6 個區間 `d_shares` 為零卻募了上億美元,硬套 $n=0$ 會讓求償權的
  減少整個消失。
- `btc` 是買進與賣出的淨額加上獨立觀測到的持幣變動,不是單一動作。

所以改成:**算術路徑維持精確,工具的對應關係改成可驗證的斷言**
(`check_operations_against_tools`),測試帶反證。
**聚合差分與工具套用不是同一種東西** —— 先前把它們看成一樣是判斷錯誤。

### ✅ 5. 建 `operations` 表與配對器

192 個操作。驗收:193 個動作全部被涵蓋、現金流差額 \$0.00、沒有重複計算。

最重要的決定是規則的依據換了:**配對看文件寫的用途,不看金額相似度。**
把「同一週同時出現賣幣與回購」當訊號,只有 1 週金額對得上(差 0.0026%),
其餘來源都遠大於用途 —— 用金額去配等於在猜。

而 8-K 的敘述句直接寫了用途,有時連金額都逐筆寫。那是 `stated`,不是推論。
2026-08-02 那份寫明 \$52.3M 用於回購,但那週回購總額 \$81.2M —— 賣幣只支應
約 64%。所以記帳分兩種:**全額支應**(差 < 5%)合併成組合操作;
**只支應一部分**則兩邊維持獨立,文件的說法掛在賣幣那一筆上。

> 用詞修正:原本寫成「部分資助」是錯的 —— 中文的「資助」是贊助、補助,
> 而這裡講的是「這筆錢拿去支付那筆開銷」,應該是**支應**。

### ✅ 6. 階段偵測器 —— 做完了,結論是「先不換」

三個邊界對上兩個,**2025-01-30 那個差了 150 天**。差異解釋得了,而解釋
就是不能換:那個邊界由可轉債發行與優先股 IPO 定義,兩者當時都不在 L3 裡。

所以這一步真正的產出是 `explained_share()` —— 把「結構在動但操作層看不到」
量化成數字。

### ✅ 7. 補齊歷史資料

424B5 / 10-Q / 10-K / XBRL companyfacts 全部歸檔。五份 IPO 公開說明書解析
驗證過,與手動輸入的面額**完全吻合**,並補上淨募資
(\$563.4M / \$711.2M / \$979.7M / \$2,474M / €608.8M)。
**可轉債的事件數從 0 變成 12。** 實付優先股股息有了逐季數字。

做這一步的交叉驗證翻出兩個既有誤讀 —— 見 [03-data.md §5](03-data.md)
與 [04-decisions.md](04-decisions.md#缺口與誤讀長得一模一樣)。
順帶把 `web/raw/*.json` 從「爬蟲輸出」改成「L2 視圖的序列化」,
關掉那條繞過 L1–L4 的旁路。

### ✅ 8. 粒度優先規則

`events.resolve_flows()`,規則與證據見 [03-data.md §2](03-data.md)。
`phases.sources_and_uses()` 讓 L4 吃得到季與年。
**「可轉債時代」的買幣從看得到 \$1.1B 變成 \$21.7B,對帳收到 4.5%。**

## 4. 下一步

### 要你拍板的(建模選擇,不是工程問題)

**`explained_share()` 要吃季頻,得先決定優先股發行按面額還是按募資金額計。**
現金口徑繞開了這題,求償權口徑繞不開。見 [07 §5](07-data-gaps.md)。

### 已知缺陷,還沒修

- **13 個「本週無買賣」的 8-K 被歸類成 `btc_sale`**(qty=0),
  `min(btc_sale)` 因此答 2025-04-06 而不是真正的 2026-05-31。
  目前不影響任何數字(金額為 0,下游都跳過),但這類查詢會答錯。
  要修得先決定給它什麼名義 —— 那是「揭露了無動作」,既不是買也不是賣。

### 工程,順序可換

1. **L3 吃季頻。** 配對靠文件敘述,而季頻來自 XBRL 標籤,沒有敘述可配 ——
   所以季頻在 L3 只能當單一操作,不能進配對器。
2. **`leverage.ts` 改讀 JSON。** 修掉 CLAUDE.md 第一條規則的違反。
3. **`build_operations()` 改由逐事件套用 Tool 產生。** 這會改變數字,
   所以要先有第 1 點。
4. **`chronicle.TOOLS` 的 LaTeX 改指向 `toolbox`。** 一條式子只留一份。
5. **抽參數收進 `extract`。** 目前散在 `build_data.py`;
   資料來源會變、語意不會,所以這一層要跟 `apply` 分開。
6. **正向模擬改用同一組 Tool。** 做完這步,「該不該做」與「做得好不好」
   才真的是同一把尺。
7. **報價 API 歸檔。** L1 唯一還沒覆蓋的來源。
