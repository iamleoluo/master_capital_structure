## 1. 現況與目標

### 現在的七頁

| 路由 | 檔案 | 行數 | 內容的性質 |
|---|---|---|---|
| `/` 總覽 | `overview.ts` + `explorer.ts` | 80 + 321 | 數值解 |
| `/chronicle` 大事記 | `chronicle.ts` | 277 | **數值解 + 觀點混在一起** |
| `/structure` 資本結構 | `structure.ts` | 186 | **公式解 + 數值解混在一起** |
| `/structure/holdings` 持幣與融資 | `accumulation.ts` | 69 | 數值解 |
| `/operations` 資本操作 | `operations.ts` | 180 | 公式解 |

| `/data-quality` 資料品質 | `dataQuality.ts` | 188 | 數值解 |

**問題不是頁數,是三處混用。** 同一頁裡既有推導又有今天的數字,
讀者分不出哪些是恆成立的、哪些是這週的。

### 目標的導覽

Router 已經支援兩層(`parent` 欄位),不需要改。

```
總覽 │ 講義 │ 儀表板 │ 觀點 │ 出處
      │       │        │
      │       │        └ 新聞 · 社論
      │       └ 量 · 工具 · 配對 · 時間      ← 數值解
      └ 量 · 工具 · 配對 · 時間              ← 公式解
```

**講義與儀表板的子分頁刻意同名同序** —— 那是「同一個 L1–L4 解兩次」
最直接的呈現。讀者在講義看到 $\Delta E$ 的式子,切到儀表板同一個分頁
就看到今天的數字。

## 2. 每一頁放什麼

### 2.1 總覽(入口,無子分頁)

一頁走完四層,每層一句話 + 一個數字 + 一個往下鑽的連結。
現有的 `explorer.ts`(可拖的時間軸)留在這裡 —— 它是最好的入口。

### 2.2 講義 · 四個子分頁(公式解,**不帶任何數字**)

| 子分頁 | 內容 | 素材來源 |
|---|---|---|
| **量** | 為什麼只需要 $H, C, S, p$;$C = D + L - U$ 與 $U$ 的兩塊;三個股數分母;$B, E, m, A, p_0$ 的定義 | `structure.ts` 的定義區、`symbols.ts` |
| **工具** | 四個位置、九把原子工具。每把的 $\Delta B / \Delta E$ 與判準。`claims` 是 `?` 的那幾把要解釋為什麼 | `operations.ts`、`toolkit.ts`、`meta.toolkit` 的 `kind: "atom"` |
| **配對** | 四個組合的代數。**路徑中間永遠是 U**;為什麼配對要看文件敘述不看金額 | `meta.toolkit` 的 `kind: "combo"` |
| **時間** | 逐日鏈結為什麼沒有殘差;為什麼用當天價格評價;四層歸因的推導 | `strategy.ts` 的方法論段落、[01-model.md §7–9](01-model.md) |

**驗收**:這四頁的 HTML 裡**不得出現任何從 `app/data` 來的數值**。
建置時掃一次,出現就讓建置失敗(見 §5)。

### 2.3 儀表板 · 四個子分頁(數值解,**不重述公式**)

| 子分頁 | 內容 | 素材來源 |
|---|---|---|
| **量** | 今天的 $H, C, S, p$ 與走勢;每個數字旁邊標實測/插值、離最近申報幾天 | `accumulation.ts`、`daily.json` |
| **工具** | 最近用了哪些工具、各多少錢 | L3 的具名操作(`operations.build`)**需要新增輸出** |
| **配對** | 實際配對出來的組合操作,含文件原句與信心度 | 同上 |
| **時間** | 四層歸因的數字、目前在哪個階段、階段的起訖 | `strategy.ts` 的結論區、`chronicle.json` |

**資料品質溶在每個數字旁邊**,不另立一頁。口徑偏差(面額 vs 市價、
粒度、插值)掛在它影響的那個數字上。

### 2.4 觀點 · 兩個子分頁

格式與機制見 [09-site.md §4](09-site.md)。
**新聞**錨在事件,**社論**錨在主張(多一個 `claim` 欄位)。

### 2.5 出處(無子分頁)

L1 檔案庫清單、稽核軌跡、每一種表單連到 EDGAR。
現有 `dataQuality.ts` 的「每個數字都指得回一份文件」那一段搬過來。

## 3. 施工順序

原則與後端重建同一條:**每一步的驗收條件都是「既有的數字不能變」。**

### 步驟 1 — 新增講義的四個子分頁(不刪舊頁)

從 `structure.ts` / `operations.ts` / `strategy.ts` 抽出**純推導**的段落。
舊頁暫時留著(內容會重複,但沒有壞掉的風險)。

- 驗收:`npx tsc --noEmit`、四頁無 console 錯誤、**數值掃描為零**
- 新增 `app/src/pages/lecture/{quantities,tools,pairing,time}.ts`

### 步驟 2 — L3 的操作輸出到 `app/data`

儀表板的「工具」與「配對」兩頁需要具名操作,但目前 `operations.build()`
的結果沒有進到 `app/data`。

- 新增 `build_data.build_operations_feed()`:每一條帶
  工具 id、期間、參數、$\Delta B/\Delta E$、信心度、文件原句、accession
- 驗收:條數與 `O.build()` 一致、對帳等式仍成立、既有五份 JSON 逐位元組不變

### 步驟 3 — 新增儀表板的四個子分頁

把 `overview.ts` / `accumulation.ts` / `dataQuality.ts` / `strategy.ts`
的**數值**段落搬過去。

- 驗收:每一個搬過去的數字與舊頁**逐字相同**(搬家不改值)

### 步驟 4 — 觀點系統

- `posts/*.md` 的格式、loader、renderer
- 圖表以 id + range 重用現有八個元件
- `pins` 快照 + 現值對照(「寫於某日 X,今天 Y」)
- 把四段 Era 敘述轉成最早的四篇社論,標上寫作日期
- 驗收:四篇的數字與 `chronicle.json` 當時的值一致;階段骨架只剩
  起訖、一句定性、主要工具

### 步驟 5 — 換導覽、刪舊頁

- `main.ts` 的 routes 換成新結構
- 刪 `pages/{overview,chronicle,structure,operations,strategy,pricing,dataQuality,accumulation}.ts`
- 驗收:全站無 404、`npm run build` 通過、黃金錨點不動

### 步驟 6 — 情境模擬器歸位

等前五步做完再決定它放講義還是獨立(見 §6)。

## 4. 不能動的東西

1. **兩個黃金錨點**(\$92.11 / \$118.31)
2. **23 條恆等式**與 368 個 Python 測試
3. **4 個 TS 測試**(情境模擬對 Python 黃金樣本)
4. `app/data/*.json` 的**數值**。重排只動呈現,搬家不改值 ——
   任何一步讓數字變了,就是做錯了

## 5. 新增的守門:講義不得有數值

這是整個重排唯一需要新機制的地方。

建置時掃 `app/src/pages/lecture/**`,出現下列任一就讓建置失敗:

- `import ... from "../../data"`(直接吃 `app/data`)
- 字面上的大數字(千分位逗號、`$` 後接數字、`sats` 前接數字)

> 允許的例外:**符號定義裡的常數**,例如 $10^{8}$、面額 \$100、
> $m > 1$ 這種門檻。它們是公式的一部分,不是觀測值。
> 例外清單要寫死在檢查裡,不能用「看起來像」判斷。

這條守門的意義與黃金錨點相同:**把一個容易在六個月後悄悄失守的規則,
變成建置時會紅的東西。**

---

## 6. 還沒決定的

1. **情境模擬器放哪。** 它是講義的公式加滑桿 —— 公式解,但很互動。
   放講義會讓講義有一頁跟其他頁性質不同;獨立一頁又破壞三分法。
2. **作者欄位寫誰。** 單人還是協作署名。
3. **總覽要不要保留可拖時間軸。** 它是最好的入口,但也是最重的元件
   (`explorer.ts` 321 行)。

## 7. 預估

| 步驟 | 規模 | 風險 |
|---|---|---|
| 1 講義四頁 | 中 —— 主要是搬與刪,推導已經寫好了 | 低 |
| 2 L3 輸出 | 小 | 低(有對帳守著) |
| 3 儀表板四頁 | 中 | 低(逐字搬) |
| 4 觀點系統 | **大 —— 唯一要新建的東西** | 中(新格式、新 loader) |
| 5 換導覽 | 小 | 中(一次性切換,要全站點過) |

**步驟 1–3 可以先做而不影響任何現有頁面**(新舊並存),
步驟 5 才是不可逆的那一刀。
