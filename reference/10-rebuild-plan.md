**問題不是頁數,是三處混用。** 同一頁裡既有推導又有今天的數字,

### 目標的導覽

Router 已經支援兩層(`parent` 欄位),不需要改。

```
總覽 │ 講義 │ 儀表板 │ 觀點 │ 出處
      │       │        │
      │       │        └ 大事記 · 資本結構
      │       └ 量 · 工具 · 配對 · 時間      ← 數值解
      └ 量 · 工具 · 配對 · 時間              ← 公式解
```

**講義與儀表板的子分頁刻意同名同序** —— 那是「同一個 L1–L4 解兩次」
最直接的呈現。讀者在講義看到 $\Delta E$ 的式子,切到儀表板同一個分頁
就看到今天的數字。

## 3. 施工順序

原則與後端重建同一條(見 [08-status.md §3](08-status.md)):
**每一步的驗收條件都是「既有的數字不能變」。** 這讓重排可以隨時停下來,
而且錯了會立刻被 23 條恆等式與 368 個測試抓到。

### 步驟 1 — 新增講義的四個子分頁(不刪舊頁)

從 `structure.ts` / `operations.ts` / `strategy.ts` 抽出**純推導**的段落,
對照 §2.2 的「推導在哪」逐節核對 —— 講義不是重寫,是把 `reference/`
已經推導好的東西搬上網頁。

- 新增 `app/src/pages/lecture/{quantities,tools,pairing,time}.ts`
- 舊頁暫時留著(內容會重複,但沒有壞掉的風險)
- **驗收**:`npx tsc --noEmit`、四頁無 console 錯誤、**數值掃描為零**(§5)

### 步驟 2 — L3 的操作輸出到 `app/data`

儀表板的「工具」與「配對」兩頁需要具名操作,但 `operations.build()`
的結果目前沒有進到 `app/data` —— 這是整個重排唯一的**資料缺口**。

- 新增 `build_data.build_operations_feed()`:每一條帶工具 id、期間、參數、
  $\Delta B/\Delta E$、信心度、文件原句、accession
- $\Delta B/\Delta E$ 要用 `toolbox.effect()` 算,不要另寫一份
  —— 理由見 [05-toolbox.md §5](05-toolbox.md)
- **驗收**:條數與 `O.build()` 一致、`O.reconcile()` 仍 ok、
  既有五份 JSON **逐位元組不變**

### 步驟 3 — 新增儀表板的四個子分頁

把 `overview.ts` / `accumulation.ts` / `dataQuality.ts` / `strategy.ts`
的**數值**段落搬過去。

- **驗收**:每一個搬過去的數字與舊頁**逐字相同**(搬家不改值)。
  做法:搬之前先把舊頁的關鍵數字抓成快照,搬完逐一比對

### 步驟 4 — 觀點系統

唯一要新建的東西,風險最高。

- `posts/*.md` 的格式(見 [09 §4.2](09-site.md))、loader、renderer
- 圖表以 id + range 重用現有八個元件,不要為文章另寫圖
- `pins` 快照 + 現值對照(「寫於某日 $X$,今天 $Y$」)
- 把四段 Era 敘述轉成最早的四篇「大事記」(它們記的就是「發生了什麼」),標上寫作日期
- **驗收**:四篇的數字與當時的 `chronicle.json` 一致;
  階段骨架只剩起訖、一句定性、主要工具,其餘全部算

### 步驟 5 — 換導覽、刪舊頁

- `main.ts` 的 routes 換成新結構
- 刪 `pages/{overview,chronicle,structure,operations,strategy,pricing,dataQuality,accumulation}.ts`
- **驗收**:全站無 404、`npm run build` 通過、黃金錨點不動、
  瀏覽器逐頁點過(這一步不可逆,要親自看過每一頁)

### 步驟 6 — 情境模擬器歸位

等前五步做完再決定它放講義還是獨立(見 §7)。
注意它是**全站唯一保有金融計算的前端程式**,由 360 筆黃金樣本釘住
(見 [01-model.md §5](01-model.md) 的警告框),搬動時那組測試要跟著。

## 5. 新增的守門

### 5.1 講義不得有數值

這是整個重排唯一需要新機制的地方。

建置時掃 `app/src/pages/lecture/**`,出現下列任一就讓建置失敗:

- `import ... from "../../data"`(直接吃 `app/data`)
- 字面上的大數字(千分位逗號、`$` 後接數字、`sats` 前接數字)

> 允許的例外:**符號定義裡的常數**,例如 $10^{8}$、面額 \$100、
> $m > 1$ 這種門檻。它們是公式的一部分,不是觀測值。
> 例外清單要寫死在檢查裡,不能用「看起來像」判斷。

### 5.2 文件宣稱的數量不得與程式漂開

`test_the_docs_do_not_claim_a_stale_tool_count`(已實作)。
由來見 §6 —— 這道是補一次實害,不是預防性的。

### 5.3 為什麼要做成會紅的東西

兩道的意義與**兩個黃金錨點**相同:
**把一個容易在六個月後悄悄失守的規則,變成建置時會紅的東西。**

這個專案已經有一整套這樣的守門(23 條恆等式、368 個測試、
黃金樣本釘住 TS 的情境模擬),重排不該是唯一沒有守門的部分。

## 6. 寫這份計畫時暴露的既有漂移(已修)

把計畫接回前面各章時,發現文件與程式已經各自漂了一段時間 ——
**而且沒有任何東西會紅**。全部修掉了,記在這裡當教訓:

| 位置 | 文件寫的 | 實際 |
|---|---|---|
| `README` / `CLAUDE.md` | 「七把工具」+「三個組合」 | 九把原子 + 四個組合 |
| [02 §4](02-operations.md) | 「三個組合」,其中 A 是「賣幣 → 增加美元儲備」 | **那是單一工具**,$U$ 本來就是賣幣的終點;而真正缺的是 ATM→買幣 與 發優先股→買幣 |
| [02 §4](02-operations.md) | 「三個有一個共同特徵:$B$ 一定下降」 | 加進 ATM→買幣 之後 $B$ 是**上升**的 |
| [02 §2](02-operations.md) | 六把單一工具 | 少了**可轉債轉股**(唯一不經過 $U$ 的工具) |
| `02:190` / `04` / `05` / `08` | 八種操作 / 八把 | 九 |

**根因**:工具清單在三個地方各寫一次(`chronicle.TOOLS`、`toolbox.TOOLS`、
各章散文),合併之後只改了程式。

**守門**:`test_the_docs_do_not_claim_a_stale_tool_count` —— 掃
`reference/*.md` 與 `CLAUDE.md` 裡「N 把工具」「N 個組合」的宣稱,
與 `len(toolbox.TOOLS)` / `len(toolbox.COMBOS)` 不符就紅。
反證驗過:改回舊數字立刻失敗。

> 這件事本身就是這份計畫要解決的問題的縮影 ——
> **同一件事寫在兩個地方,就一定會漂。**
> 重排的目的不是好看,是讓「公式解」與「數值解」各自只有一個來源。

## 7. 還沒決定的

1. **情境模擬器放哪。** 它是講義的公式加滑桿 —— 公式解,但很互動。
   放講義會讓講義有一頁跟其他頁性質不同;獨立一頁又破壞三分法。
2. **作者欄位寫誰。** 單人還是協作署名。
3. **總覽要不要保留可拖時間軸。** 它是最好的入口,但也是最重的元件
   (`explorer.ts` 321 行)。

## 8. 預估

| 步驟 | 規模 | 風險 |
|---|---|---|
| 1 講義四頁 | 中 —— 主要是搬與刪,推導已經寫好了 | 低 |
| 2 L3 輸出 | 小 | 低(有對帳守著) |
| 3 儀表板四頁 | 中 | 低(逐字搬) |
| 4 觀點系統 | **大 —— 唯一要新建的東西** | 中(新格式、新 loader) |
| 5 換導覽 | 小 | 中(一次性切換,要全站點過) |

**步驟 1–3 可以先做而不影響任何現有頁面**(新舊並存),
步驟 5 才是不可逆的那一刀。

### 接手時先做的三件事

1. 讀 [CLAUDE.md](../CLAUDE.md) 最前面的「公式解 vs 數值解」—— 整份計畫都建立在那張表上
2. `python3 web/refresh.py --dry-run` 確認資料新鮮度
3. `python3 -m pytest tests/ -q && python3 reference/verify.py` 確認起點是綠的
